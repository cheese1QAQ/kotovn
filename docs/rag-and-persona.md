# 动态 RAG（边翻边学）与人物人格模板设计（目标 #3 & #4）

---

## 1. 混合 RAG 知识库架构

视觉小说翻译的知识一致性痛点无法靠单一向量库解决：向量相似度擅长找“语义相关剧情”，却容易漏掉短小的**专有名词（如 2 个汉字的人名/技能名）**。因此 KotoVN 采用 **三层混合知识存储**：

| 存储层 | 存储内容 | 检索方式 | 解决的 VN 核心痛点 |
| :--- | :--- | :--- | :--- |
| **L1：精确术语表（Glossary）** | 人名、地名、组织、招式、固定敬称映射 | 精确字符串/Trie（Aho-Corasick）全量扫描 | 专有名词 100% 召回，避免前后译名飘移 |
| **L2：语义记忆库（Episodic Memory）** | 按场景/对话窗口聚合的剧情片段与摘要 | Dense Embedding（ONNX CPU）+ BM25 混合检索 + 轻量重排 | 长距离伏笔、前文语境、代词指代消解 |
| **L3：轻量关系图（Entity Graph）** | `(角色A) --[关系 / 互称 / 敬语等级]--> (角色B)` | 按当前 `speaker` + 场景在场角色精确查表 | 解决日语高频省略主语、同一人面对不同对象语气突变的问题 |

### 关键特性：面向多分支与 SL（读档）的 Checkpoint 快照
视觉小说玩家经常存档/读档（Save/Load）走不同角色线路。若知识库只增不减，A 线学到的“恋人称呼”或剧情秘密会污染 B 线。
* **设计方案**：知识库每次重大场景切换或手动触发时记录轻量级增量快照（`Snapshot(snapshot_id, label, glossary_ids, relation_ids, created_at)`），支持一键回滚或按 `route_name` 分叉知识库分支。

## 2. “边翻边学”即时维护管线（Online RAG Maintenance）

为了**绝不拖慢前台游戏阅读体验**，RAG 维护采用**双速异步设计**：

1. **前台热路径（目标耗时 < 1.5s）**：只读 L1/L2/L3 知识库，不做任何提取写入。
2. **后台异步 Reflector（冷路径）**：
   - 每积累 `N` 句对话（默认 `N=5`）或检测到场景大幅切换时，将最近窗口原文 + 译文打包送入异步队列。
   - Reflector 使用轻量结构化 Prompt（可复用本地同一 LLM 的空闲间隙，避免双倍内存占用），增量抽取：
     - `new_glossary`：新出现的专有名词、暂定译名、词类（人物/地点/术语）与依据例句。
     - `relation_updates`：新识别的称呼变化（如从“前辈”改口直呼其名）。
     - `episode_summary`：压缩为 1–2 句长期剧情记忆写入 L2。
3. **去重、冲突消解与无感人工兜底**：
   - 新词写入前先查 L1 是否已存在或与现有词高相似；若冲突不覆盖 `verified` 条目，而是记为冲突候选。
   - **状态机**：自动提取的词条默认为 `draft`（草稿态，已可辅助后续翻译并在悬浮窗以淡色下划线提示）；用户仅在发现译名不满意时悬停点击修正，该词立即锁定为 `verified`（永久优先），无需打开复杂管理页。

## 3. 人物人格模板引擎（Persona Engine）

目标是让本地轻量化模型（3B–8B）翻译出的角色台词**生动、有辨识度、不“翻译腔”**。

### 3.1 人格卡片结构（`PersonaCard`）
摒弃空泛的“她是一个活泼的女孩”式长段描述，改用面向本地小模型优化的**结构化语言学指纹 + Few-Shot 锚点**：
* **`archetype_base`**：继承的原型范本 ID（如 `tsundere`、`ojou_sama`、`kuudere`）。
* **`linguistic_fingerprint`（语言学指纹）**：
  - `self_pronoun_map`：日语自称到中文自称的映射（如 `わたくし -> 本小姐 / 我`、`俺 -> 老子 / 我`）。
  - `sentence_endings`：常用句尾语气词与禁止词（例如大小姐禁用粗口，倾向用“呢”“罢了”“真是的”）。
  - `politeness_level`：正式/随性/粗鲁等级（1–5）。
  - `punctuation_style`：短句停顿、省略号或感叹号倾向。
* **`style_anchors`（Few-Shot 黄金例句）**：3–8 组「原文 + 语境标签 + 高水准目标译文」。每次翻译仅动态检索最匹配当前情绪/场景的 Top-3 注入 Prompt，控制 Token 开销在 ~250 tokens 以内。

### 3.2 两阶段构建与演化路径（兼容“先读屏、后解包”）

1. **阶段一：跨作品范本库预构建（Archetype Library，现已内置原型模板）**
   - 从经典已汉化视觉小说中提炼高复用角色原型模板（存放在 `backend/src/kotovn/persona/templates/*.yaml`）。
   - 每个范本提供通用的语言指纹和跨作品可迁移的 Few-Shot 风格例句。
2. **阶段二-A：实时读屏模式下的冷启动与自适应（Phase 1–3 主路径）**
   - 当识别到新说话人名字（如 `千夏`），若尚无专属卡片：
     - 结合 VLM 观察到的立绘印象 + 前 3–5 句台词，后台自动从范本库匹配最接近的 `archetype_base` 生成初始 `PersonaCard`（`status=auto_inferred`）。
     - 随游戏推进，Reflector 持续收集该角色的高辨识度台词，自动覆盖（Override）其专属口癖与人称偏好，越翻越贴脸。
3. **阶段二-B：未来剧本解包模式下的全量脚本校准（预留 `ScriptSource` 扩展）**
   - 后续接入剧本解包器后，可直接按说话人聚合整部作品台词：
     - 统计高频自称、句尾模式与平均句长；
     - 自动匹配 Top-K 原型范本做加权融合，并用该角色真实台词覆盖差异特征，一次性生成高质量全员人格库。
